# ChessSummon / Chess of Dark GDD

- 문서 버전: 2.1
- 프로젝트 버전: 0.8.2
- 최종 동기화: 2026-09-23
- 구현 기준: `src`, `server`, `electron`, `tests`, `package.json`
- 배포 대상: Windows 포터블, 단일 HTML, Steam 후보 빌드

## 1. 한 줄 정의

5×5 보드에서 매 턴 얻는 마나로 체스 말을 왕 주변에 소환하고, 이동·포획·체크 압박을 조합해 상대 왕을 제거하거나 체크메이트하는 짧고 밀도 높은 다크 판타지 전술 게임이다.

## 2. 핵심 사용자와 플레이 상황

주 사용자는 체스 퍼즐과 소환형 전략을 좋아하지만 긴 정통 체스 대국보다 10~30분 안에 전술적 결론이 나는 플레이를 선호하는 PC 전략 게이머다. 대표 페르소나는 29세 전략 게임 이용자 신유준이며, 기대하는 재미는 말을 소환해 이동 경로와 공격선을 동시에 설계하는 두뇌전이다.

## 3. 문제 정의

이 게임의 차별점인 소환은 이동·포획·체크 규칙과 동시에 이해해야 한다. 따라서 플레이어가 현재 가능한 행동, 행동 후 마나 변화, 체크 위협과 다음 선택을 한 화면에서 읽지 못하면 핵심 재미보다 규칙 부담을 먼저 느끼게 된다. 현재 UX의 최우선 목표는 새 시스템 추가보다 행동 전후의 전술 정보를 더 빠르게 이해시키는 것이다.

## 4. 디자인 기둥

1. **소환으로 바뀌는 전장**: 고정된 초기 전력 대신 마나와 소환 순서가 매 판 다른 전선을 만든다.
2. **작은 보드의 높은 밀도**: 5×5 공간에서 한 칸의 이동이 공격선·왕 안전·소환 공간을 동시에 바꾼다.
3. **짧고 읽히는 수읽기**: MOVE, CAPTURE, SUMMON, CHECK, WIN 단서를 행동 전에 보여준다.
4. **반복 가능한 경쟁**: 4단계 AI, 싱글 MMR, 서버 권위 PvP와 랭크로 숙련도를 확인한다.

## 5. 핵심 루프

난이도 또는 멀티플레이 선택 → 초기 폰 배치 → 턴 시작과 마나 획득 → 말 이동/포획 → 선택적 소환 → 턴 종료 → 상대 행동 → 왕 제거 또는 체크메이트 → 결과·MMR·전술 복기 → 다음 소환/편성 판단 → 재대전.

## 8. 난이도와 AI

| 난이도 | 시작 흐름 | AI 특징 | 해금 |
|---|---|---|---|
| 쉬움 | 자동 배치, 튜토리얼 선택 가능 | 입문용 판단 | 기본 |
| 보통 | 자동 배치 | 균형형 | 기본 |
| 어려움 | 폰 4개 수동 배치 | 더 강한 탐색 | 기본 |
| 매우 어려움 | 폰 4개 수동 배치 | 어려움보다 깊은 탐색 | `hard_win` 업적 필요 |

AI 기본 탐색 깊이는 3이며, 매우 어려움은 어려움보다 더 깊은 수읽기를 수행한다. AI 사고 연출 기본 지연은 600ms다.

## 9. 튜토리얼과 전술 정보

쉬움 시작 시 튜토리얼 여부를 선택한다. 튜토리얼은 말 선택 → 이동 → 소환 버튼 → 소환 위치 → 체크 설명 → 턴 종료 → 완료의 7단계로 진행된다. 실전에서는 선택 말의 모든 합법 목적지에 이동 후 양측 압력을 계산해 `안전`, `교환`, `위험` 태그를 표시하고, 포획 후보는 `처치 · 상태`로 구분한다. HUD에는 `이동4 안전2 위험1 처치1`처럼 선택 결과를 압축해 표시한다. 소환 기여도와 왕 위협 전후 비교는 아직 미구현이다.

## 10. 진행과 랭크

싱글 플레이 MMR은 로컬 저장소에 보관한다. 기본 1000, 하한 800, 상한 1200이며 승리 +12, 패배 -10이다. PvP 결과에는 싱글 MMR을 적용하지 않는다.

| 랭크 | 최소 MMR |
|---|---:|
| Bronze | 0 |
| Silver | 900 |
| Gold | 1100 |
| Platinum | 1300 |
| Diamond | 1500 |
| Master | 1750 |

## 11. 멀티플레이

WebSocket 대기열은 두 플레이어를 방에 매칭한다. 서버가 보드·턴·시계·이동·소환·종료를 소유하고 잘못된 턴, 소유권, 불법 이동·소환, 종료 후 명령을 거부한다. 연결 종료는 서버 몰수패로 처리한다. 서버가 결과를 생성하고 로컬 JSON 랭크 저장소에 기본 1000점과 승패를 기록하며, 랭크 결과는 Steam `RANK_POINTS` 어댑터로 전달할 수 있다. 상대를 찾지 못하면 랭크 기반 AI 대전으로 전환하는 경로가 있다.

## 12. 업적과 Steam 연동

Steam 서비스는 브리지가 없는 HTML·일반 데스크톱 환경에서 조용히 폴백한다. 브리지가 있으면 업적, 통계, 랭크 점수 업로드, Steam ID, 리더보드 조회를 사용한다. 첫 출시용 업적 10개 이상, 업적 통계 5개 이상, `RANK_POINTS` 리더보드 정의가 코드와 테스트로 확인된다.

Steam 출시 완료 조건에는 HTML·루트 포터블·release 포터블 산출물, 두 포터블의 SHA-256 일치, 6초 실행 스모크, App ID, 캡슐·스크린샷·트레일러, 싱글·튜토리얼·재시작·오버레이 수동 QA가 포함된다.

## 14. 시청각 방향

다크 네이비·금색 프레임과 밝고 어두운 목재 보드로 전술 정보와 다크 판타지 분위기를 함께 전달한다. 플레이어와 상대는 색상뿐 아니라 말 이미지와 HUD 위치로 구분한다. Kenney CC0 기반 선택, 이동, 소환, 포획, 승리, 패배 SFX가 실제 행동에 연결돼 있다. 체크메이트 시 보드를 공개하고 왕 위치에 전용 연출을 재생한다.

## 15. 저장과 호환

싱글 MMR, 닉네임, 업적 진행 등 로컬 상태는 브라우저/Electron 저장 경로를 사용한다. Steam 환경에서는 Electron IPC·preload 브리지를 통해 Steam 기능을 호출한다. 릴리스 채널은 `desktop`, `steam`, `html`, `dev`로 구분하며 화면에 버전과 채널 정보를 표시한다.

## 18. 검증 현황

2026-09-23 기준 `npm test` 실행 결과 38개 테스트 파일, 225개 테스트가 모두 통과했다. `npm run build`가 통과했고 Impeccable 정적 감지는 0건이었다. 요청 범위에 따라 `npm run dist`, 루트 실행파일 교체, Drive 배포는 실행하지 않았다. 실제 플레이 화면, 450×800 좁은 화면, 저장 복귀와 Steam 클라이언트 동작은 수동 검증하지 않았다. Vite는 약 1.59MB JavaScript 청크가 500kB를 넘는다는 경고를 남긴다.

## 19. 알려진 리스크

- 450×800 세로형 UI는 정보 밀도가 높아 작은 글자와 다국어 긴 문자열 검증이 계속 필요하다.
- HTML에서는 Steam 기능이 폴백되므로 플랫폼별 기능 차이를 명확히 안내해야 한다.
- 공개 PvP 운영에는 서버 배포, 장애 대응, 부정행위 모니터링과 개인정보 정책이 코드 외 운영 과제로 남는다.
- Steam 출시에는 App ID·상점 자산·트레일러·실클라이언트 오버레이 QA가 필요하다.
- 이동 위험도는 현재 보드 압력만 계산하며 소환 기여도와 왕 위협 변화까지 통합하지 않는다.
- 현재 복원 소스 계보는 v0.8.2이고 Drive에는 소스가 아닌 `17_ChessSummon_v1.1.0_portable.exe`만 있다. 버전 숫자가 더 높은 실행파일을 현재 소스의 상위 계보로 단정하거나 덮어쓰지 않는다.

## 20. 다음 개발 우선순위

1. **소환 기여도 통합**: 현재 이동 위험 태그에 소환 전후 점유율과 왕 위협 변화를 연결한다.
2. **실플레이 UX QA**: 450×800 실제 화면에서 전술 태그, 소환 카드, 긴 한글 문구의 겹침과 가독성을 검증한다.
3. **Steam 출시 체크 해소**: App ID, 캡슐·스크린샷·트레일러, 오버레이와 포터블 스모크 항목을 실제 값으로 완료한다.
4. **온보딩 유지 검증**: 튜토리얼 완료율, 첫 승리까지 걸린 판수, 재대전율을 수집한다.

## 21. 2026-09-23 결과에서 다음 전투로 이어지는 피드백

전투 종료 시 남은 마나, 소환 종류별 횟수, 양측 잔존 전력을 결과 화면으로 전달한다. `resultTacticalPlan`은 시간패, 주력 소환 없음, 전력 열세, 승리한 주력 전개의 순서로 조건을 판정해 `첫 소환`, `병사 거점 보존`, `주력 소환 유지` 중 하나의 다음 행동을 보여준다. 정답을 자동 실행하지 않고 다음 판에 시험할 한 가지 판단만 제안한다. 기존 트로피·프레임·색상·버튼 자산은 그대로 사용하며 새 이미지는 추가하지 않았다.
