# ChessSummon Steam 출시 계획서

작성일: 2026-06-01
대상 버전: v0.1.18 이후 출시 준비 빌드

## 1. 출시 판단 요약

ChessSummon은 현재 싱글 플레이, 튜토리얼, 난이도 선택, 로컬 WebSocket 기반 멀티 로비, 닉네임 기반 랭크 포인트 저장까지 갖춘 상태다. 다만 Steam 출시 기준으로 보면 멀티 플레이와 랭킹은 아직 "출시 가능한 온라인 시스템"이라기보다 프로토타입에 가깝다.

출시 전 핵심 판단은 다음과 같다.

- 싱글 플레이 중심 출시: 비교적 빠르게 가능하다.
- Steam 랭킹 포함 출시: Steamworks Stats/Leaderboards 연동이 필요하다.
- 온라인 매칭 포함 출시: Steam Lobby 또는 자체 매칭 서버 설계가 필요하다.
- 랭크 대전 포함 출시: 인증, 대국 동기화, 결과 검증, 부정행위 방지 정책이 필요하다.

추천 방향은 1차 출시를 싱글 플레이와 Steam 랭킹/업적 중심으로 준비하고, 온라인 매칭은 베타 또는 출시 후 업데이트로 분리하는 것이다.

## 2. 현재 멀티/랭크 구현 상태

### 구현된 것

- `server/multiplayer-server.cjs`
  - Node HTTP 서버와 WebSocket 업그레이드 핸드셰이크를 직접 구현한다.
  - 접속 시 닉네임을 받아 계정을 생성하거나 조회한다.
  - 빠른 매칭 요청이 오면 대기 중인 다른 플레이어와 `roomId`를 만들어 매칭 완료 메시지를 보낸다.

- `server/rankStore.cjs`
  - 신규 계정 기본 랭크 포인트는 1000점이다.
  - 승자는 +15점, 패자는 -15점으로 기록할 수 있다.
  - 랭크 데이터는 `data/rank-points.json`에 저장된다.

- `src/scenes/MultiplayerLobbyScene.js`
  - 닉네임을 입력받는다.
  - 로컬 WebSocket 서버에 접속한다.
  - 계정명, 랭크 포인트, 대기열, 매칭 완료 상태를 표시한다.

- `tests/RankStore.test.js`
  - 계정 생성, 닉네임 정규화, 승패 랭크 변경을 검증한다.

### 아직 구현되지 않은 것

- 매칭 후 실제 온라인 대국 시작
- 양쪽 클라이언트의 보드 상태 동기화
- 이동/소환/턴 종료 명령의 네트워크 전송
- 서버 권위 판정 또는 대국 결과 검증
- 연결 끊김, 재접속, 포기패 처리
- Steam 계정 인증
- Steam Leaderboard 업로드
- Steam에서 보이는 공식 랭킹 페이지 연동

## 3. Steam 매칭 시스템 판단

Steam에서 멀티 매칭을 보여주려면 현재 로컬 WebSocket 서버만으로는 부족하다. Steam 공식 매칭 흐름은 사용자가 멀티플레이를 선택하면 조건에 맞는 로비를 검색하고, 없으면 로비를 만들고, 충분한 플레이어가 모이면 게임 서버 또는 호스트에 연결하는 방식이다.

ChessSummon의 선택지는 세 가지다.

### A안: Steam Lobby 기반 P2P 매칭

Steam Lobby로 방 생성, 검색, 친구 초대, 빠른 입장을 처리한다. 실제 대국 데이터는 한 플레이어를 호스트로 두고 P2P 또는 Steam Networking 쪽으로 흘린다.

장점:
- 별도 매칭 서버 비용이 작다.
- Steam 친구 초대와 오버레이 흐름을 살리기 좋다.
- 1:1 턴제 게임과 잘 맞는다.

단점:
- 호스트 이탈, 결과 조작, 연결 품질 이슈를 게임에서 처리해야 한다.
- 랭크 대전의 신뢰도가 낮아질 수 있다.

적합도:
- 캐주얼 친선전, 비랭크 빠른 대전에는 적합하다.
- 공식 랭크전은 추가 검증 없이는 위험하다.

### B안: 자체 권위 서버 기반 매칭

현재 `server/multiplayer-server.cjs`를 확장해 Steam ID 인증, 대기열, 방 생성, 대국 상태, 결과 판정을 서버가 관리한다.

장점:
- 랭크 결과 신뢰성이 높다.
- 결과 조작과 중도 이탈 처리를 통제하기 쉽다.
- 나중에 시즌 랭킹, 리플레이, 신고 기능으로 확장하기 좋다.

단점:
- 서버 운영 비용과 배포/모니터링이 필요하다.
- 출시 전 QA 범위가 크게 늘어난다.
- 네트워크 장애 대응과 보안 구현 부담이 생긴다.

적합도:
- 공식 랭크전, 시즌 랭킹, 장기 운영을 목표로 한다면 가장 맞다.

### C안: 1차 출시에서는 온라인 매칭 제외

Steam 출시는 싱글 플레이, 튜토리얼, 업적, Steam Leaderboard 중심으로 하고, 멀티는 "개발 중" 또는 별도 베타 브랜치로 둔다.

장점:
- 출시 리스크가 가장 낮다.
- 게임의 핵심 재미와 상점 반응을 먼저 검증할 수 있다.
- QA와 검수 범위를 줄일 수 있다.

단점:
- 상점에서 "온라인 멀티"를 핵심 기능으로 말하기 어렵다.
- 랭크 대전 기대감을 바로 제공하지 못한다.

적합도:
- 현재 상태에서는 가장 현실적인 1차 출시안이다.

## 4. Steam 랭킹 시스템 판단

현재 랭크 포인트는 로컬 JSON 파일에 저장된다. 이 방식은 개발 중 테스트에는 충분하지만 Steam에서 보이는 랭킹으로는 사용할 수 없다.

Steam에서 유저에게 보이는 랭킹을 만들려면 Steamworks의 `ISteamUserStats` 기반 Leaderboard를 사용해야 한다. Steam API는 stats, achievements, leaderboards 접근과 제출 기능을 제공한다. 리더보드 점수는 `FindLeaderboard` 또는 `FindOrCreateLeaderboard`로 핸들을 얻은 뒤 업로드하고, 다운로드 API로 순위 데이터를 가져오는 구조다.

### 필요한 리더보드

1차 출시 기준 추천 리더보드:

- `RANK_POINTS`
  - 정렬: 높은 점수 우선
  - 값: 현재 랭크 포인트
  - 표시: 숫자

- `HARD_AI_WINS`
  - 정렬: 높은 점수 우선
  - 값: 어려움 난이도 승리 수
  - 표시: 숫자

- `FASTEST_WIN_SECONDS`
  - 정렬: 낮은 점수 우선
  - 값: 승리까지 걸린 초
  - 표시: 시간

1차 출시에서는 `RANK_POINTS` 하나만 넣고 안정화한 뒤 확장해도 된다.

### 랭크 포인트 정책

현재 고정 +15/-15 방식은 이해하기 쉽지만 실제 랭크 매칭에는 약하다. 출시 전에는 아래 중 하나를 선택해야 한다.

- 단순 점수제: 승리 +15, 패배 -15
  - 구현이 쉽고 예측 가능하다.
  - 실력 차이를 반영하지 못한다.

- Elo 유사 점수제
  - 상대 점수에 따라 증감폭이 달라진다.
  - 랭크 대전 느낌이 강해진다.

- 싱글 플레이 랭킹제
  - 온라인 대전 결과가 아니라 어려움 승리, 클리어 시간, 연승 등을 랭킹화한다.
  - 부정행위 방지는 약하지만 1차 출시 리스크가 낮다.

추천은 1차 출시에서 싱글 플레이 기반 리더보드를 먼저 넣고, 공식 랭크 대전 점수는 온라인 대국 검증이 끝난 뒤 공개하는 것이다.

## 5. 출시 전 필수 작업 목록

### Steamworks 기본 준비

- Steamworks 파트너 등록
- Steam Direct 앱 크레딧 결제
- 앱 생성
- 상점 페이지 작성
- 스크린샷, 캡슐 이미지, 트레일러 준비
- 콘텐츠 설문, 언어, 가격, 출시일 설정
- Windows 빌드 업로드 구조 정리

### Steam 연동

- Electron 환경에서 Steamworks SDK 연동 방식 결정
- Steam App ID 분기 처리
- 개발 중 `steam_appid.txt` 처리
- Steam Overlay 동작 확인
- Steam Cloud 저장 경로 설계
- Steam Stats/Achievements 정의
- Steam Leaderboard 정의

### 매칭/온라인

- 1차 출시 범위 결정: 친선전, 랭크전, 또는 보류
- Steam Lobby 기반인지 자체 서버 기반인지 결정
- 대국 명령 프로토콜 정의
- 보드 상태 동기화 테스트
- 연결 끊김/타임아웃/포기패 처리
- 결과 검증과 랭크 반영 정책 작성

### QA

- 싱글 플레이 전체 플로우
- 튜토리얼 완료 플로우
- 다시하기 반복
- 모든 난이도 전투 시작
- 제한시간 3분 체스 시계 및 30초 무입력 경고 동작
- UI 글자 잘림/겹침
- Steam 실행 환경
- 저장/불러오기
- 리더보드 업로드 실패 시 오프라인 처리

## 7. 현재 질문에 대한 결론

### 매칭 시스템이 스팀에서 잘 동작할까?

현재 상태 그대로는 어렵다. 지금 구현은 로컬 서버에 접속해 두 명을 짝지어주는 수준이다. Steam 출시용 매칭으로 보려면 Steam Lobby 연동 또는 외부 권위 서버 운영이 필요하고, 매칭 후 실제 대국 동기화가 반드시 추가되어야 한다.

### 스팀에서 보여줄 랭킹이 잘 동작할까?

현재 로컬 랭크 포인트는 Steam에서 보이지 않는다. Steam Leaderboard에 점수를 업로드하는 별도 연동이 필요하다. 다만 구조상 랭크 포인트 개념은 이미 있으므로, `rankStore`를 Steam Leaderboard 업로드 계층과 연결하는 방향으로 확장할 수 있다.

### 지금 가장 좋은 출시 전략은?

1차 출시는 싱글 플레이 완성도, 튜토리얼, 업적, Steam Leaderboard 중심으로 가고, 온라인 매칭과 공식 랭크전은 베타 또는 출시 후 업데이트로 분리하는 것이 좋다. 이렇게 해야 출시 리스크를 낮추면서도 스팀 페이지에서는 "랭킹 지원"을 명확하게 보여줄 수 있다.
