# Multiplayer and MMR Release Assessment

Updated: 2026-06-12  
Version: v0.1.94

## Conclusion

Multiplayer and MMR are possible, but the current build should not be marketed as full human ranked PvP yet.

| Item | Current state | Launch judgment |
| --- | --- | --- |
| AI fallback matchmaking | Implemented | OK for first Steam release |
| Local MMR/rank point save | Implemented with JSON rank store | OK for testing and AI-match presentation |
| Steam leaderboard adapter | Implemented as an optional upload path | Needs Steam App ID and SDK QA |
| Two-human online match | Lobby matching only | Not ready for release |
| Official ranked MMR | Concept exists | Blocked until server authority and Steam identity are added |

## What Already Works

- `server/multiplayerCore.cjs` can put two queued clients into a room.
- `server/rankStore.cjs` creates nickname accounts at 1000 points and stores wins, losses, and rank point changes.
- `src/scenes/MultiplayerLobbyScene.js` falls back to an AI match when matchmaking takes too long.
- The fallback AI difficulty is chosen from the player's rank point band.
- `SteamService.uploadRankPoints()` gives the game a path to upload `RANK_POINTS` when Steamworks is available.

## What Is Still Missing For Real PvP

- Steam account identity must replace nickname-only rank identity.
- The server must own the board state, clocks, placements, legal moves, summons, captures, turn changes, and final results.
- Both clients must transition from the lobby into the same synchronized game session.
- Disconnect, reconnect, timeout, and surrender handling must be deterministic.
- MMR changes must be generated by the server, not by a client-provided `winnerName`.

## Recommended Steam Launch Scope

First Steam release:

- Ship single-player, tutorial, difficulty modes, local progress, Steam achievements, and leaderboard adapter.
- Keep multiplayer framed as AI fallback / ranking preview, or mark true PvP as beta if shown.
- Do not promise "online ranked PvP" on the Steam store page yet.

Post-launch or beta:

- Build server-authoritative PvP.
- Bind accounts to Steam IDs.
- Replace fixed +15/-15 with Elo-like MMR after result validation is trustworthy.
- Add manual two-account Steam QA before public ranked release.

## Code Readiness Gate

The release gate lives in `src/multiplayer/releaseReadiness.js`.

- `ai_fallback` should be complete for the first Steam release.
- `public_pvp` should remain blocked until the server-authoritative items pass.
